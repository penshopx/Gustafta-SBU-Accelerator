Berikut adalah uji integrasi PostgreSQL terisolasi yang memverifikasi bahwa kolom `existingSbuExpiresOn` benar-benar menjadi NULL setelah PATCH, dan kolom lain tidak berubah.

### 1. Struktur Uji di `artifacts/api-server/test/sbu-assessment-route.test.mjs`

```javascript
import { describe, it, beforeAll, afterAll, mock } from 'node:test';
import assert from 'node:assert';
import { setupRestrictedPgTest } from './setup/postgres-restricted.mjs';
import { app } from '../src/app.mjs';
import supertest from 'supertest';
import { eq } from 'drizzle-orm';
import { sbuAssessments } from '@workspace/db/schema';

describe('SBU Assessment PostgreSQL Integration — null date handling', () => {
  let pgSetup;
  let request;
  let adminSql;
  let restrictedDb;
  let schemaName;

  beforeAll(async () => {
    pgSetup = await setupRestrictedPgTest();
    adminSql = pgSetup.adminSql;
    restrictedDb = pgSetup.restrictedDb;
    schemaName = pgSetup.schemaName;

    // Jalankan migrasi di skema sementara menggunakan koneksi admin
    // await migrate(drizzle(adminSql), { migrationsFolder: './drizzle' });

    mock.module('../src/db/index.mjs', {
      namedExports: { db: restrictedDb }
    });

    request = supertest(app);
  });

  afterAll(async () => {
    mock.reset();
    if (pgSetup) await pgSetup.teardown();
  });

  it('should persist NULL for existingSbuExpiresOn and leave other columns untouched', async () => {
    const testUserId = 'user_test_null_date';
    const assessmentId = 'assessment_test_null_date';

    // 1. SISIPKAN DATA AWAL: permohonan dengan tanggal terisi dan data lain yang spesifik
    const initialDate = '2026-06-15';
    const initialCompanyName = 'PT Uji Tanggal Null';
    const initialQualification = 'Kecil';

    await adminSql`
      INSERT INTO ${adminSql(schemaName)}.sbu_assessments (
        id, user_id, company_name, qualification, existing_sbu_expires_on, updated_at, created_at
      ) VALUES (
        ${assessmentId},
        ${testUserId},
        ${initialCompanyName},
        ${initialQualification},
        ${initialDate}::date,
        NOW() - INTERVAL '1 day',
        NOW() - INTERVAL '2 days'
      )
    `;

    // 2. Rekam snapshot kolom lain sebelum PATCH (kecuali updatedAt yang memang akan berubah)
    const beforeRow = await adminSql`
      SELECT company_name, qualification, created_at, existing_sbu_expires_on, updated_at
      FROM ${adminSql(schemaName)}.sbu_assessments
      WHERE id = ${assessmentId}
    `;
    assert.strictEqual(beforeRow.length, 1);
    assert.strictEqual(beforeRow[0].existing_sbu_expires_on.toISOString().slice(0, 10), initialDate);

    // 3. PATCH hanya dengan existingSbuExpiresOn: null
    //    Gunakan header X-SBU-Form-Owner sesuai pedoman proyek
    const patchRes = await request
      .patch(`/api/cases/${assessmentId}`)
      .set('X-SBU-Form-Owner', testUserId)
      .set('Cookie', `__session=test-session-for-${testUserId}`)
      .send({ existingSbuExpiresOn: null });

    assert.strictEqual(patchRes.status, 200, `PATCH gagal: ${patchRes.text}`);

    // 4. GET dan verifikasi tanggal null dari respons API
    const getRes = await request
      .get(`/api/cases/${assessmentId}`)
      .set('Cookie', `__session=test-session-for-${testUserId}`);

    assert.strictEqual(getRes.status, 200);
    assert.strictEqual(
      getRes.body.existingSbuExpiresOn,
      null,
      'GET harus mengembalikan null untuk existingSbuExpiresOn'
    );

    // 5. Verifikasi langsung di PostgreSQL: kolom DATE benar-benar NULL
    const afterRow = await adminSql`
      SELECT company_name, qualification, created_at, existing_sbu_expires_on, updated_at
      FROM ${adminSql(schemaName)}.sbu_assessments
      WHERE id = ${assessmentId}
    `;
    assert.strictEqual(afterRow.length, 1);
    assert.strictEqual(
      afterRow[0].existing_sbu_expires_on,
      null,
      'Kolom existing_sbu_expires_on di PostgreSQL harus NULL, bukan tanggal lama'
    );

    // 6. Verifikasi kolom lain tidak berubah (kecuali updatedAt)
    assert.strictEqual(afterRow[0].company_name, initialCompanyName, 'company_name berubah');
    assert.strictEqual(afterRow[0].qualification, initialQualification, 'qualification berubah');
    assert.strictEqual(
      afterRow[0].created_at.getTime(),
      beforeRow[0].created_at.getTime(),
      'created_at tidak boleh berubah'
    );
    assert.ok(
      afterRow[0].updated_at.getTime() > beforeRow[0].updated_at.getTime(),
      'updatedAt harus maju setelah PATCH'
    );
  });
});
```

### 2. Poin Verifikasi Kunci

| Aspek | Cara Verifikasi |
|---|---|
| **NULL di database** | `afterRow[0].existing_sbu_expires_on === null` (bukan string kosong, bukan tanggal lama) |
| **GET mengembalikan null** | `getRes.body.existingSbuExpiresOn === null` |
| **Kolom lain utuh** | Bandingkan `company_name`, `qualification`, `created_at` sebelum dan sesudah PATCH |
| **updatedAt maju** | `afterRow[0].updated_at > beforeRow[0].updated_at` |
| **Data terisolasi** | Semua operasi lewat skema `test_schema_<uuid>`, bukan `public` |

### 3. Jebakan yang Perlu Diwaspadai

1. **Drizzle `set({ ... })` dengan `undefined` vs `null`**: Jika logika PATCH di `sbu.ts` menggunakan spread operator dan field bernilai `undefined`, Drizzle akan mengabaikan kolom tersebut (tidak menulis apa-apa). Pastikan kode PATCH secara eksplisit meneruskan `null` ke `set()`, bukan `undefined`.

2. **PostgreSQL `DATE` vs `TIMESTAMP`**: Kolom `existing_sbu_expires_on` bertipe `DATE`. Saat dibaca kembali via `postgres.js`, ia akan menjadi objek `Date` dengan waktu `00:00:00 UTC`. Jika kode perbandingan menggunakan `.toISOString()`, pastikan memotong ke 10 karakter pertama (`YYYY-MM-DD`).

3. **Mock sesi**: Pengujian ini mengasumsikan ada mekanisme untuk menautkan cookie sesi ke `userId`. Sesuaikan bagian `.set('Cookie', ...)` dengan cara aplikasi Anda memetakan sesi ke pengguna di lingkungan uji (mungkin via mock modul auth).

4. **Header `X-SBU-Form-Owner`**: Sesuai pedoman proyek yang baru disepakati, header ini melengkapi pemeriksaan kepemilikan, bukan menggantikannya. Server harus memverifikasi bahwa header cocok dengan identitas sesi yang sah sebelum melanjutkan ke pemeriksaan kepemilikan.

### 4. Jika Pengujian Gagal

Jika `afterRow[0].existing_sbu_expires_on` masih berisi tanggal lama, kemungkinan besar logika PATCH di `sbu.ts` melakukan sesuatu seperti:

```typescript
// ❌ SALAH: undefined diabaikan oleh Drizzle
await db.update(sbuAssessments)
  .set({ existingSbuExpiresOn: body.existingSbuExpiresOn ?? undefined })
  .where(...);

// ✅ BENAR: null ditulis secara eksplisit
await db.update(sbuAssessments)
  .set({ existingSbuExpiresOn: body.existingSbuExpiresOn ?? null })
  .where(...);
```

Atau, jika menggunakan validasi Zod, pastikan skema memperbolehkan `null`:

```typescript
const patchSchema = z.object({
  existingSbuExpiresOn: z.string().date().nullable().optional(),
});
```

Uji ini akan langsung mengungkap masalah semacam itu karena memverifikasi state database secara langsung, bukan hanya respons API.
