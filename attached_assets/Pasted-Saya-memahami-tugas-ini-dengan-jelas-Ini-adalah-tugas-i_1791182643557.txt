### 1. Perbaikan Routing di Workspace Gustafta (Menangani `text/html`)
Masalah HTTP 200 `text/html` pada endpoint API biasanya terjadi karena *fallback routing* aplikasi SPA (Single Page Application) yang menangkap semua rute yang tidak dikenal dan menyajikan `index.html`.

**Tindakan yang diperlukan di Workspace Gustafta:**
Pastikan rute API didefinisikan **sebelum** *fallback* statis. 
```javascript
// Contoh struktur routing di server Gustafta (bukan SBU)
app.get('/api/v1/ruang-simpan/company-profile', ruangSimpanProfileHandler);
// ... rute API lainnya ...
// FALLBACK HARUS PALING AKHIR
app.get('*', (req, res) => res.sendFile(path.join(__dirname, 'public/index.html')));
```

---

### 2. Protokol Provisioning Secret (Strict Compliance)
Sesuai instruksi, **jangan pernah** menempelkan *secret* atau token di chat, frontend, atau upload. 
- Gunakan mekanisme **Secrets** resmi dari platform hosting/deployment Anda.
- Pastikan variabel lingkungan `RUANG_SIMPAN_CONNECTIONS` dikonfigurasi per lingkungan (staging/production) dengan format yang memetakan `sbu_user_id` ke `ruang_simpan_owner_id` dan `scoped_token` (hanya dengan *scope* `profile:read`).
- Contoh format konfigurasi (untuk diisi di dashboard Secrets, bukan di kode):
  ```env
  # RUANG_SIMPAN_CONNECTIONS (JSON string atau format env khusus platform Anda)
  {
    "sbu_user_123": { "ownerId": "rs_owner_abc", "token": "rs_token_xyz_readonly" },
    "sbu_user_456": { "ownerId": "rs_owner_def", "token": "rs_token_uvw_readonly" }
  }
  ```

### 3. Implementasi Backend SBU (`artifacts/api-server/src/routes/ruang-simpan.ts`)
Endpoint ini harus bertindak sebagai *proxy* yang aman, tanpa menyimpan data ke DB lokal, dan dengan penanganan error yang ketat.

```typescript
import { Router, Request, Response } from 'express';
import { fetchRuangSimpanProfile } from '../lib/ruang-simpan'; // Asumsi fungsi helper ada di sini

const router = Router();

router.get('/company-profile', async (req: Request, res: Response) => {
  // 1. Autentikasi SBU: Identitas harus sah
  const sessionUserId = req.auth?.userId; 
  if (!sessionUserId) {
    return res.status(401).json({ error: 'Sesi tidak valid atau kedaluwarsa' });
  }

  try {
    // 2. Panggil helper yang menangani pemetaan secret dan fetch ke upstream
    // Helper ini TIDAK BOLEH menulis ke DB, hanya mengambil data live.
    const profileData = await fetchRuangSimpanProfile(sessionUserId);

    // 3. Header Keamanan: Mencegah caching di browser atau proxy
    res.setHeader('Cache-Control', 'no-store, no-cache, must-revalidate, proxy-revalidate');
    res.setHeader('Pragma', 'no-cache');
    res.setHeader('Expires', '0');

    // 4. Kembalikan data profil sumber (boleh kosong jika sah)
    return res.json(profileData);

  } catch (error: any) {
    // 5. Pemetaan Error Ketat (Tanpa membocorkan PII atau Token)
    const status = error.status || 500;
    
    // Jangan log detail error yang mengandung token atau PII ke console production
    // Hanya log kode error dan jenis kegagalan untuk debugging internal
    console.error(`[RuangSimpan Proxy Error] User: ${sessionUserId}, Status: ${status}, Type: ${error.type || 'UNKNOWN'}`);

    if (status === 401) {
      return res.status(401).json({ error: 'Token akses kedaluwarsa atau dicabut' });
    }
    if (status === 403) {
      return res.status(403).json({ error: 'Izin ditolak: Tidak memiliki akses profile:read' });
    }
    if (status === 429) {
      return res.status(429).json({ error: 'Batas permintaan tercapai, silakan coba lagi nanti' });
    }
    if (status === 503) {
      return res.status(503).json({ error: 'Layanan Ruang Simpan sedang tidak tersedia' });
    }

    return res.status(500).json({ error: 'Gagal mengambil profil perusahaan' });
  }
});

export default router;
```

### 4. Implementasi Frontend (`artifacts/gustafta-sbu/src/components/company-profile-page.tsx`)
Komponen ini harus memastikan bahwa saat akun berganti atau dimuat ulang, data lama **tidak** bocor atau ditampilkan sementara.

```tsx
import { useState, useEffect } from 'react';

export function CompanyProfilePage({ currentUserId }: { currentUserId: string }) {
  // State dipisahkan per jenis status untuk menghindari kebocoran data lama
  const [profile, setProfile] = useState<any>(null);
  const [isLoading, setIsLoading] = useState(false);
  const [error, setError] = useState<{ status: number; message: string } | null>(null);

  useEffect(() => {
    // Reset state sepenuhnya saat currentUserId berubah (mencegah data lama tampil)
    setProfile(null);
    setError(null);
    
    if (!currentUserId) {
      setError({ status: 401, message: 'Silakan masuk untuk melihat profil.' });
      return;
    }

    const fetchProfile = async () => {
      setIsLoading(true);
      setError(null);
      try {
        const res = await fetch('/api/v1/ruang-simpan/company-profile', {
          credentials: 'include', // Mengirim cookie sesi SBU
          headers: {
            'Accept': 'application/json',
            // Cache-control request untuk memastikan browser tidak melayani dari cache
            'Cache-Control': 'no-cache'
          }
        });

        if (!res.ok) {
          const errData = await res.json().catch(() => ({}));
          throw { status: res.status, message: errData.error || 'Gagal memuat profil' };
        }

        const data = await res.json();
        setProfile(data); // Data boleh null/empty jika itu respons sah dari upstream
      } catch (err: any) {
        setError({ status: err.status || 500, message: err.message });
        setProfile(null); // Pastikan profile null saat error
      } finally {
        setIsLoading(false);
      }
    };

    fetchProfile();
  }, [currentUserId]); // Dependency array memastikan fetch ulang saat akun berganti

  if (isLoading) return <div>Memuat profil perusahaan...</div>;

  if (error) {
    return (
      <div className="p-4 bg-red-50 text-red-700 rounded border border-red-200">
        <p className="font-bold">Error {error.status}</p>
        <p>{error.message}</p>
        {error.status === 401 && <p>Silakan muat ulang halaman atau masuk kembali.</p>}
      </div>
    );
  }

  if (!profile) {
    return (
      <div className="p-4 bg-gray-50 text-gray-600 rounded border border-gray-200">
        <p>Belum ada data profil perusahaan yang terhubung, atau profil sumber kosong.</p>
      </div>
    );
  }

  return (
    <div className="p-4 border rounded">
      <h2 className="text-xl font-bold mb-4">Profil Perusahaan (Live)</h2>
      {/* Render data profil di sini. JANGAN render dokumen, hanya metadata profil */}
      <pre className="bg-gray-100 p-2 rounded text-sm overflow-auto">
        {JSON.stringify(profile, null, 2)}
      </pre>
    </div>
  );
}
```

### 5. Protokol Pengujian Live (Checklist Wajib)
Pengujian sintetis (mock) **tidak diterima** sebagai bukti keberhasilan. Berikut adalah checklist yang harus diverifikasi secara *live* di lingkungan yang sesuai:

- [ ] **Identitas & Pemisahan Akun:** Login sebagai Pengguna A, profil Pengguna A muncul. Logout, login sebagai Pengguna B. Profil Pengguna A **tidak** muncul (harus kosong atau profil B).
- [ ] **Profil Sumber Kosong yang Sah:** Jika upstream mengembalikan objek kosong `{}` atau `null` yang valid, frontend menampilkannya sebagai "Belum ada data", bukan error.
- [ ] **Header `no-store`:** Inspeksi Network tab browser. Respons `company-profile` harus memiliki header `Cache-Control: no-store`.
- [ ] **Error 401 (Token Kedaluwarsa/Dicabut):** Cabut/ubah secret di backend untuk Pengguna A. Muat ulang halaman. Harus muncul pesan 401 yang jelas, dan **tidak ada** data profil lama yang terlihat.
- [ ] **Error 403 (Izin):** Ubah scope token menjadi sesuatu selain `profile:read` (misal: `doc:read`). Harus mengembalikan 403.
- [ ] **Error 429 & 503:** Simulasikan (jika memungkinkan di lingkungan staging) pembatasan rate atau downtime upstream. Frontend harus menampilkan pesan error yang sesuai, bukan crash atau loading tak berujung.
- [ ] **Tidak Ada Penulisan DB:** Pantau log database SBU selama pengujian. Tidak boleh ada query `INSERT` atau `UPDATE` ke tabel profil yang dipicu oleh endpoint ini.
- [ ] **Tidak Ada PII/Token di Log:** Periksa log server SBU. Tidak boleh ada string token Ruang Simpan atau data PII sensitif yang tercetak.
