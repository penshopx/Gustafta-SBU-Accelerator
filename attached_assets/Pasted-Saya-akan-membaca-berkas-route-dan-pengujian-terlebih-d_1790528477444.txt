## Ringkasan Perubahan

### Pengujian Lintas Pengguna (Cross-User Access Control)

**Berkas:** `artifacts/api-server/test/sbu-assessment-route.test.mjs`

**8 pengujian baru** ditambahkan dalam blok `describe('Cross-user access control')`:

| # | Skenario | Ekspektasi |
|---|----------|------------|
| 1 | `GET /api/sbu/assessments` — Pengguna A | Hanya melihat 2 kasus miliknya, tidak ada kasus Pengguna B |
| 2 | `GET /api/sbu/assessments` — Pengguna B | Hanya melihat 1 kasus miliknya, tidak ada kasus Pengguna A |
| 3 | `GET /api/sbu/assessments/:id` — ID milik orang lain | `404` (sama seperti ID tidak ada) |
| 4 | `GET /api/sbu/assessments/:id` — ID tidak ada | `404` |
| 5 | `PATCH /api/sbu/assessments/:id` — ID milik orang lain | `404` |
| 6 | `DELETE /api/sbu/assessments/:id` — ID milik orang lain | `404` + verifikasi kasus asli masih ada |
| 7 | `GET /evidence` — kasus milik orang lain | `404` |
| 8 | `POST /evidence` — kasus milik orang lain | `404` |

**Poin kunci implementasi:**
- Dua token berbeda dibuat untuk Pengguna A (`user-A-123`) dan Pengguna B (`user-B-456`).
- Pengguna A membuat 2 kasus, Pengguna B membuat 1 kasus.
- Setiap pengujian memverifikasi isolasi data antar pengguna.
- Akses ke ID milik orang lain **selalu mengembalikan `404`** — berperilaku identik dengan ID yang tidak ada (mencegah enumerasi ID).
- Filter pemilik di `sbu.ts` sudah berfungsi dengan benar; pengujian ini menutup celah cakupan untuk memastikan isolasi data lintas pengguna.

**Total pengujian:** 47 (semua lulus tanpa regresi).
