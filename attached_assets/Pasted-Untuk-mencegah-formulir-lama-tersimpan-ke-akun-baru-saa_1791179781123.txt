Untuk mencegah formulir lama tersimpan ke akun baru saat sesi berganti di tab lain, kita harus menerapkan pertahanan berlapis (*defense-in-depth*): **Validasi Kepemilikan di Server** (lapisan paling kritis) dan **Penguncian Formulir di Klien** (untuk UX yang lebih baik).

Berikut adalah langkah-langkah audit dan perbaikannya:

### 1. Lapisan Server: Validasi Kepemilikan (Wajib)
Di `artifacts/api-server/src/routes/sbu.ts`, kita tidak bisa hanya mengandalkan sesi yang aktif. Server **harus** memverifikasi bahwa `userId` dari sesi yang sedang aktif adalah pemilik sah dari data yang ingin diubah. Jika sesi berganti, `userId` di sesi akan berbeda dengan `userId` pemilik data, dan server harus menolaknya.

**`artifacts/api-server/src/routes/sbu.ts`**
```typescript
import { eq } from 'drizzle-orm';
// ... impor db, schema, dll

// Contoh untuk endpoint pembaruan kasus
app.patch('/api/cases/:id', async (req, res) => {
  // 1. Ambil userId dari sesi yang sedang aktif (misal: dari token Clerk/JWT)
  const sessionUserId = req.auth?.userId; 
  const caseId = req.params.id;

  if (!sessionUserId) {
    return res.status(401).json({ error: 'Sesi tidak valid atau kedaluwarsa' });
  }

  // 2. Ambil data kasus yang ada dari database
  const existingCase = await db.query.cases.findFirst({
    where: eq(cases.id, caseId)
  });

  if (!existingCase) {
    return res.status(404).json({ error: 'Kasus tidak ditemukan' });
  }

  // 3. PERTAHANAN UTAMA: Validasi kepemilikan (Ownership Check)
  // Jika sesi berganti di tab lain, sessionUserId akan menjadi milik pengguna baru,
  // sehingga tidak akan cocok dengan existingCase.userId.
  if (existingCase.userId !== sessionUserId) {
    // Kembalikan 403 Forbidden (atau 404 untuk mencegah enumerasi data)
    return res.status(403).json({ 
      error: 'Akses ditolak: Sesi tidak cocok dengan pemilik data ini' 
    });
  }

  // 4. Lanjutkan dengan pembaruan jika valid
  await db.update(cases)
    .set({ ...req.body, updatedAt: new Date() })
    .where(eq(cases.id, caseId));
    
  return res.json({ success: true });
});

// Terapkan pola yang sama untuk PATCH /api/evidence/:id dan PATCH /api/me
```

### 2. Lapisan Klien: Deteksi Perubahan Sesi Lintas Tab
Di `artifacts/gustafta-sbu/src/App.tsx`, kita perlu mendeteksi jika sesi berubah di tab lain. Karena cookie tidak memicu event JavaScript secara langsung, kita bisa menggunakan `localStorage` sebagai mekanisme sinyal (*signaling mechanism*).

**`artifacts/gustafta-sbu/src/App.tsx`**
```tsx
import { useEffect } from 'react';
// Asumsi Anda memiliki hook atau state untuk melacak ID sesi saat ini

export default function App() {
  // ... state dan logic auth lainnya

  useEffect(() => {
    // Dengarkan perubahan localStorage untuk mendeteksi perubahan sesi di tab lain
    const handleStorageChange = (e: StorageEvent) => {
      // Sesuaikan 'auth-session-id' dengan key yang digunakan aplikasi Anda 
      // untuk menyimpan ID sesi/token saat login/logout
      if (e.key === 'auth-session-id' && e.oldValue !== e.newValue) {
        // Berikan sinyal ke seluruh aplikasi bahwa sesi telah berubah secara eksternal
        window.dispatchEvent(new CustomEvent('external-session-change'));
      }
    };

    window.addEventListener('storage', handleStorageChange);
    return () => window.removeEventListener('storage', handleStorageChange);
  }, []);

  // ... return JSX aplikasi
}
```

### 3. Lapisan Klien: Penguncian Formulir
Di `artifacts/gustafta-sbu/src/components/case-evidence.tsx` (dan komponen formulir lainnya), dengarkan sinyal tersebut. Jika sesi berubah di tab lain, kunci formulir di tab ini agar tombol simpan tidak bisa diklik, mencegah pengguna secara tidak sengaja mengirim data dengan cookie baru.

**`artifacts/gustafta-sbu/src/components/case-evidence.tsx`**
```tsx
import { useState, useEffect } from 'react';

export function CaseEvidenceForm({ caseId, initialData }) {
  const [isFormLocked, setIsFormLocked] = useState(false);
  const [isSubmitting, setIsSubmitting] = useState(false);

  useEffect(() => {
    const handleExternalSessionChange = () => {
      // Kunci formulir segera untuk mencegah pengiriman dengan cookie sesi yang baru
      setIsFormLocked(true);
      
      // Jika Anda menggunakan React Query, Axios, atau fetch dengan AbortController,
      // batalkan permintaan yang sedang berjalan di sini.
      // abortController.abort(); 
    };

    window.addEventListener('external-session-change', handleExternalSessionChange);
    return () => window.removeEventListener('external-session-change', handleExternalSessionChange);
  }, []);

  const handleSave = async (data) => {
    if (isFormLocked) return; // Cegah pengiriman jika formulir sudah terkunci
    
    setIsSubmitting(true);
    try {
      const response = await fetch(`/api/cases/${caseId}`, {
        method: 'PATCH',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify(data),
      });

      // Tangani kasus di mana server menolak karena sesi tidak cocok (Lapisan 1 gagal atau dilewati)
      if (response.status === 403 || response.status === 401) {
        setIsFormLocked(true);
        alert('Sesi Anda telah berubah atau kedaluwarsa. Perubahan tidak disimpan untuk keamanan. Silakan muat ulang halaman.');
        return;
      }

      // ... handle success
    } catch (error) {
      // ... handle network error
    } finally {
      setIsSubmitting(false);
    }
  };

  return (
    <form onSubmit={handleSubmit(handleSave)}>
      {isFormLocked && (
        <div className="bg-yellow-100 text-yellow-800 p-3 mb-4 rounded border border-yellow-300">
          <strong>Sesi telah berubah di tab lain.</strong> Formulir ini dikunci untuk mencegah penulisan data ke akun yang salah secara tidak sengaja. Silakan muat ulang halaman.
        </div>
      )}
      
      {/* Input fields untuk bukti... */}
      
      <button 
        type="submit" 
        disabled={isFormLocked || isSubmitting}
        className="bg-blue-600 text-white px-4 py-2 rounded disabled:opacity-50"
      >
        {isSubmitting ? 'Menyimpan...' : 'Simpan Bukti'}
      </button>
    </form>
  );
}
```

### Ringkasan Pertahanan:
1. **Server (Paling Aman)**: Meskipun klien mengirim permintaan dengan cookie baru, server akan melihat bahwa `userId` di cookie baru tidak cocok dengan `userId` pemilik kasus, dan mengembalikan `403 Forbidden`. Data tidak akan pernah tertimpa.
2. **Klien (UX)**: Mendeteksi perubahan sesi lintas tab dan mengunci formulir. Pengguna tidak akan bingung mengapa data mereka "hilang" atau tersimpan di akun lain, karena mereka diberi tahu secara proaktif untuk memuat ulang halaman.
3. **Fallback Klien**: Jika pengguna somehow melewati penguncian formulir (misal: menggunakan DevTools), penanganan error `403/401` di klien akan tetap menangkap penolakan dari server dan mengunci formulir setelahnya.
